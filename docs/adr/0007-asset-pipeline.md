# ADR 0007: Asset pipeline: folders set priority, budgets fail the build

| | |
|---|---|
| Status | Accepted |
| Date | 11 Oct 2026 |

## Context

The game must show the lantern within 5 seconds of a cold start on a headset, and free CC0 models, textures and sounds are about to arrive. IWSDK's `AssetManager` already loads by priority (`critical` blocks `World.create`, `background` starts after it, `lazy` waits until used) with a 30 s timeout per asset, and the scene editor's Assets panel lists whatever the manifest (`src/app/assets.ts`, `defineAssets`) declares. Today the manifest holds only editor stand-ins (spheres and flat boxes, ADR 0006), and the candle, the paper and the room are procedural, so nothing is downloaded but code. We want a new file to be one step to add, and a heavy file to be caught before it reaches a headset.

## Decision

1. **Files in `src/assets` are the manifest.** `src/app/assets.ts` globs `src/assets/**` (Vite's `import.meta.glob` with `?url`, so the bundler fingerprints the file and the editor and the page get the same URL) and adds one entry per file, after the existing stand-ins. The id is the file name without folder or extension, in lower case with hyphens (`Paper Crow.glb` is `paper-crow`). Two files with one id, a file reusing a stand-in's id, or an id starting `primitive-` (IWSDK's own shapes) is an error when the manifest loads. Models must be single-file `.glb`: a `.gltf` points at separate files that are neither shipped nor checked. Extensions must be lower case. `check:budgets` fails on a `.gltf`, a `.bin` or an upper-case extension in `src/assets`, so they cannot be silently missing. Vite writes files under 4 KB into the JavaScript as `data:` URLs instead of separate files; they work, and they count towards the bundle. A `.glb` dropped into `src/assets/models/` while the editor is running appears in its Assets panel within seconds, with no restart (tried live), and loads by id.
2. **The first folder under `src/assets` sets the priority.** `critical/`: `critical`, so the world waits for it. This is risky by design: IWSDK waits up to 30 s for it, and one missing or failing critical file rejects `World.create` and leaves a blank page. Keep it empty or tiny, committed to the repository, and prefer loading the paper's texture through the loader (below) while the procedural paper shows. `audio/`: `background` (loads after the critical files, never blocks). Anything else: `lazy`, fetched when first used or prefetched. A deeper folder named `critical` or `audio` changes nothing.
3. **Budgets** (`src/engine/services/assets/budgets.mjs`, the one copy of the rules, used by the game's code, the unit tests and the CI script): each texture 512 KB, each model 500 KB, each sound effect 300 KB, each music file (audio in a folder named `music`) 1.5 MB, all critical files together 1 MB, and the first-load JavaScript 800 KB gzipped (674 KB today, mostly IWSDK and three.js). The limits are for files as shipped, so compress textures (WebP or KTX2) and audio (Ogg or MP3) first. They are file sizes only: a small WebP can still decode to a very large texture in GPU memory, so keep texture dimensions modest (2048 pixels or less) until a memory budget exists.
4. **The build enforces them.** `npm run build` runs `scripts/check-budgets.mjs --bundle` after `vite build`, which checks the first-load bundle in `dist/`, and `npm run check` runs `check:budgets`, which checks the asset files in the repository (no build needed). Files in `dist/` are not checked one by one, since Vite flattens their folders and the same files are checked at their source. Over budget, CI's check fails; that blocks merging only if the repository requires the check to pass. On `main` the Pages workflow runs `npm run build`, so an over-budget file there stops the deploy.
5. **Later loads never stall the game.** `AssetLoader` (`src/engine/services/assets/asset-loader.ts`, with `iwsdk-assets.ts` for the IWSDK side) is for lazy and background assets: its own 8 s timeout per try, one retry, one shared load for simultaneous callers, and a stand-in instead of a rejection. A stand-in is not permanent: after 10 s the next `get` tries again (or call `retry(id)`), so a file that arrives late, or one asked for before the world existed, recovers. `shortenAssetTimeout()`, called after `World.create`, makes IWSDK abandon a stuck request after 8 s, so a retry really fetches again (IWSDK shares one request per URL). A loaded model is one shared object: take copies with `AssetManager.getGLTF(id)`. The editor stand-ins (`piece-*`, `marker-*`) are renderable prototypes the loader does not load.
6. **Cold start is measured, not guessed.** `npm run build`, then `npm run cold-start` loads the production build with an empty cache, CPU slowed 4 times (`--cpu`) and fast 4G, and prints when the world was created and when the first frame's update began.

## Consequences

- At the time of writing, on a desktop, headless Chromium (software drawing): first frame about 1.7 to 2.1 s at 4 times slower CPU and about 1.9 to 2.0 s at 6 times, across several runs, with about 760 KB transferred (the 674 KB first-load bundle plus the world-initializer chunk and the scene file, which load before the first frame). The mark is set as the first update starts, before the draw, which follows within tens of milliseconds; the first complete frame was seen about 70 ms later, and the next frames stalled for about a second. This is the 2D page: on a headset the lantern is seen after tapping Enter VR, which is not included. The headset will be slower, so the 5 s goal has room but is only confirmed on a Pico or Quest.
- The paper wall is procedural, so nothing is `critical` yet. The critical total stays 0 until a paper texture is added.
- Textures are not compressed for the GPU automatically: if a texture is large in memory, use KTX2.
- No limit on texture dimensions or GPU memory yet.
